JSON Formatter (DAM JSON Editor) - QA test cases

Environment: AEM as a Cloud Service author (publish only for SE-06)
Users: QA author (can modify /content/dam/aemcloudproject/qa-json), QA read-only user (read only)
Test data folder: /content/dam/aemcloudproject/qa-json
Test files: sample.json, broken.json (trailing comma), numbers.json (12345678901234567890 and 1.0), array.json, compact.json (one line), crlf.json (Windows line endings), bom.json (UTF-8 with BOM), latin1.json (ISO-8859-1), hostile.json (<img src=x onerror=alert(1)> value), large.json (3-4 MB), unedited.json, scratch.json, image.png, a FOLDER named folder.json
Inbox items: a workflow with a participant step (e.g. Request for Activation) on sample.json, unedited.json and image.png

Known behaviour (not defects): last save wins (earlier content kept as a version); a tree edit re-indents the whole file to 2 spaces; dam:sha1 is not updated on save; very large files may load slowly.

=== 9. Security and API ===

SE-01 | High | Negative | Save request with wrong Content-Type is refused
